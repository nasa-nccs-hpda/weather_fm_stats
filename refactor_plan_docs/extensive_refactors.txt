WEATHER MODELING STATS PIPELINE - CODE QUALITY ANALYSIS AND REFACTORING PLAN
================================================================================

Document Purpose: Comprehensive analysis of code quality issues and concrete
refactoring recommendations for the weather modeling statistics pipeline.

Target Audience: AI coding agents with access to the full codebase

================================================================================
ISSUE #1: BATCHDATASETPROCESSOR IS A GOD CLASS
================================================================================

Location
--------
File: model/dataset_processor.py
Size: ~2000 lines
Class: BatchDatasetProcessor

Current State
-------------
Single class handles all dataset processing responsibilities:

1. Configuration Management
   - Parse YAML files with SafeLoader
   - Validate required parameters
   - Convert date ranges and intervals
   - Store model names and settings

2. Grid Operations
   - Create target grids (lat/lon arrays)
   - Calculate latitude-based weights (cos(lat))
   - Validate grid compatibility

3. Template Resolution
   - Parse file path templates with date variables
   - Support shift syntax: {init_YYYYMMDD,shift=-3h}
   - Handle multi-collection fallback logic
   - Glob pattern matching

4. Variable Management
   - Normalize variable names (e.g., T500, not t500)
   - Resolve case-insensitive aliases
   - Track variable collections (default, slices, aerosol)
   - Parse 3D vs 2D variable lists

5. Regridding
   - Create xESMF regridders with conservative_normed method
   - Cache regridders by grid dimensions
   - Apply regridding to variables

6. File Discovery
   - Search multiple directories for existing datasets
   - Validate dataset contents against requirements
   - Handle forecast exclusion date logic

7. Validation
   - Check variables exist in source files
   - Verify pressure levels available
   - Validate calculable variable dependencies
   - Special handling for Prithvi model levels

8. Dataset Loading
   - Open netCDF files with xarray
   - Select pressure levels
   - Normalize time coordinate names
   - Handle multi-lead vs single-lead forecast files

9. Variable Calculation
   - Calculate D2m from Q2m and PS using MetPy
   - Calculate LOGAOD from AOD
   - Calculate Z from H (geopotential height)
   - Calculate PM25 from multiple aerosol species
   - Track dependencies between calculated variables

10. Dataset Combining
    - Merge multiple time points into structured arrays
    - Build init_date × lead dimensions for forecasts
    - Build time dimension for analysis/climatology
    - Handle missing data gracefully

11. Climatology Interpolation
    - Calculate monthly weights based on day of month
    - Interpolate between adjacent months
    - Handle month boundaries (Dec→Jan, etc.)

12. Metadata Management
    - Add exclusion date metadata to forecasts
    - Set variable attributes (long_name, units)
    - Apply scaling factors
    - Handle coordinate attributes

13. File I/O
    - Generate descriptive output filenames
    - Save with compression and encoding
    - Handle chunked dimensions
    - Clean up temporary coordinates

14. Chunk/Collection Merging
    - Merge forecast chunk files along init_date
    - Merge collection-specific files
    - Delete temporary files after merge

Problems This Causes
---------------------
- Cannot test individual responsibilities in isolation
- Must read entire 2000-line class to understand any single method
- Changes to one area risk breaking unrelated functionality
- Cannot reuse components (e.g., just the regridding logic)
- New contributors overwhelmed by class size
- Difficult to mock for testing
- Multiple reasons for class to change (violates Single Responsibility)

Recommended Solution
--------------------
Split into 11 focused classes, each with single responsibility:

CLASS: ConfigManager
Purpose: Parse and validate YAML configuration
Methods:
  - load_from_yaml(path) -> Config
  - validate_config(config) -> ValidationResult
  - parse_date_range(fdates_str, spacing, exclusions) -> List[datetime]
  - convert_interval(hours) -> str  # e.g., 12 -> "120000"
Dependencies: yaml, datetime
Outputs: Typed Config object with all validated settings

CLASS: GridManager
Purpose: Create and manage spatial grids
Methods:
  - create_target_grid(nlat, nlon, delta_lat, delta_lon) -> xr.Dataset
  - calculate_latitude_weights(lats, lons) -> xr.DataArray
  - validate_grid_compatibility(nlat, nlon, delta_lat, delta_lon) -> bool
Dependencies: numpy, xarray
Outputs: Grid datasets with coordinate arrays and weight arrays

CLASS: FileResolver
Purpose: Resolve file path templates to actual files
Methods:
  - resolve_template(template, date_vars, base_dir) -> List[str]
  - parse_shift_syntax(template) -> str  # Handle {var,shift=-3h}
  - find_files(templates, date_vars, base_dir) -> str or None
  - get_date_variables(init_date, valid_time) -> Dict[str, str]
Dependencies: glob, os, re, datetime
Outputs: Actual file paths matching templates

CLASS: VariableMapper
Purpose: Manage variable names and aliases
Methods:
  - normalize_name(var_name) -> str  # T500 format
  - resolve_alias(var_name, available_vars) -> str or None
  - get_collection_variables(collection_name) -> Dict[str, List[str]]
  - parse_variable_collections(config) -> Dict
Dependencies: None (pure string manipulation)
Outputs: Normalized variable names and collection mappings

CLASS: RegridManager
Purpose: Handle spatial regridding operations
Methods:
  - get_or_create_regridder(source_grid, target_grid) -> xe.Regridder
  - regrid_variable(data, regridder) -> xr.DataArray
  - clear_cache() -> None
State: Cache of regridders by grid dimensions
Dependencies: xesmf, xarray
Outputs: Regridded data arrays on target grid

CLASS: VariableCalculator
Purpose: Calculate derived variables
Methods:
  - can_calculate(var_name) -> bool
  - get_dependencies(var_name) -> List[str]
  - calculate(var_name, dependency_data) -> xr.DataArray
  - calculate_d2m(q2m, ps) -> xr.DataArray  # Dewpoint
  - calculate_logaod(aod) -> xr.DataArray
  - calculate_z(h) -> xr.DataArray  # Geopotential
  - calculate_pm25(components) -> xr.DataArray
Dependencies: metpy, numpy, xarray
Outputs: Calculated variable arrays

CLASS: DatasetValidator
Purpose: Validate dataset contents
Methods:
  - validate_variables(file_path, required_vars) -> ValidationResult
  - validate_pressure_levels(file_path, required_levels) -> ValidationResult
  - check_calculable_dependencies(file_path, calc_vars) -> ValidationResult
  - handle_prithvi_levels(available_levels, requested_levels) -> Mapping
Dependencies: xarray
Outputs: ValidationResult with found/missing items

CLASS: DatasetLoader
Purpose: Load datasets from files
Methods:
  - load_dataset(file_path) -> xr.Dataset
  - select_pressure_levels(dataset, levels) -> xr.Dataset
  - normalize_coordinates(dataset) -> xr.Dataset  # time vs valid_time
  - select_variables(dataset, var_list) -> xr.Dataset
Dependencies: xarray
Outputs: Loaded and prepared xarray Datasets

CLASS: DatasetCombiner
Purpose: Combine multiple datasets into structured arrays
Methods:
  - combine_forecast(data_by_init_and_lead) -> xr.Dataset
  - combine_analysis(data_by_time) -> xr.Dataset
  - combine_climatology(data_by_cycle, valid_times) -> xr.Dataset
  - merge_collections(collection_datasets) -> xr.Dataset
Dependencies: xarray
Outputs: Combined datasets with proper dimensions

CLASS: ClimatologyProcessor
Purpose: Handle monthly climatology interpolation
Methods:
  - calculate_monthly_weights(datetime) -> Tuple[weight1, weight2]
  - interpolate_months(data, month1, month2, weights) -> xr.DataArray
  - process_climatology_for_time(clim_data, datetime) -> xr.Dataset
Dependencies: calendar, datetime, xarray
Outputs: Time-interpolated climatology data

CLASS: DatasetWriter
Purpose: Save datasets to NetCDF files
Methods:
  - generate_filename(dataset_type, config, chunk_id) -> str
  - prepare_for_save(dataset, scale_vars, add_metadata) -> xr.Dataset
  - save_dataset(dataset, path, compression) -> None
  - merge_chunk_files(chunk_paths, output_path) -> bool
Dependencies: xarray, os, glob
Outputs: NetCDF files on disk

Benefits of This Split
-----------------------
- Each class has ~100-200 lines (manageable size)
- Clear single responsibility for each class
- Can test each class independently with focused unit tests
- Can reuse components (e.g., use GridManager in other projects)
- Easy to understand what each class does
- Changes isolated to relevant class
- New developers can contribute to one class at a time
- Can mock individual dependencies for testing

Migration Strategy
------------------
1. Create new empty class files
2. Copy methods from BatchDatasetProcessor to appropriate new class
3. Update method signatures to accept dependencies as parameters
4. Add tests for each new class
5. Update BatchDatasetProcessor to use new classes internally
6. Once stable, replace BatchDatasetProcessor calls with new classes
7. Deprecate BatchDatasetProcessor

NEW FILE: model/variable_registry.py
Purpose: Centralized variable metadata and calculation logic

class VariableRegistry:
    """
    Central registry for variable metadata and calculations.
    
    Can load from YAML config or use defaults.
    Validates internal consistency.
    """
    
    def __init__(self, config_path: str = None):
        """
        Initialize registry.
        
        Args:
            config_path: Optional path to variable config YAML
                        If None, uses hard-coded defaults
        """
        if config_path:
            self._load_from_yaml(config_path)
        else:
            self._load_defaults()
        
        self._validate()
    
    def get_scale_factor(self, var_name: str) -> float:
        """
        Get scaling factor for variable.
        
        Args:
            var_name: Variable name (case-insensitive)
        
        Returns:
            Scale factor (default 1.0 if not found)
        """
        return self.scale_map.get(var_name.upper(), 1.0)
    
    def get_units(self, var_name: str) -> str:
        """Get units for variable (e.g., 'K', 'm/s')"""
        return self.unit_map.get(var_name.upper())
    
    def get_long_name(self, var_name: str) -> str:
        """Get descriptive name for variable"""
        return self.long_name_map.get(var_name.upper())
    
    def is_calculable(self, var_name: str) -> bool:
        """Check if variable can be calculated from others"""
        return var_name in self.calculable_vars
    
    def get_dependencies(self, var_name: str) -> List[str]:
        """
        Get dependency variables needed to calculate this variable.
        
        Raises:
            ValueError: If variable is not calculable
        """
        if not self.is_calculable(var_name):
            raise ValueError(f'{var_name} is not a calculable variable')
        return self.calculable_vars[var_name]
    
    def calculate(self, var_name: str, 
                  dependency_data: Dict[str, xr.DataArray]) -> xr.DataArray:
        """
        Calculate derived variable from dependencies.
        
        Args:
            var_name: Name of variable to calculate
            dependency_data: Dict mapping dependency names to data arrays
        
        Returns:
            Calculated data array
        
        Raises:
            ValueError: If dependencies missing or calculation fails
        """
        if not self.is_calculable(var_name):
            raise ValueError(f'{var_name} is not calculable')
        
        # Dispatch to specific calculation method
        calculator = self._calculators.get(var_name)
        if not calculator:
            raise ValueError(f'No calculator registered for {var_name}')
        
        return calculator(dependency_data)
    
    def _calculate_d2m(self, deps: Dict[str, xr.DataArray]) -> xr.DataArray:
        """Calculate 2m dewpoint from Q2m and PS"""
        q2m_with_units = deps['Q2m'] * units('kg/kg')
        ps_with_units = deps['PS'] * units.Pa
        dewpoint_celsius = mpcalc.dewpoint_from_specific_humidity(
            ps_with_units, q2m_with_units)
        kelvin_values = dewpoint_celsius.values + 273.15
        return xr.DataArray(
            kelvin_values,
            coords=dewpoint_celsius.coords,
            dims=dewpoint_celsius.dims
        )
    
    def _calculate_logaod(self, deps: Dict[str, xr.DataArray]) -> xr.DataArray:
        """Calculate log of AOD"""
        return np.log(deps['AOD'] + 0.01)
    
    def _calculate_z(self, deps: Dict[str, xr.DataArray]) -> xr.DataArray:
        """Calculate geopotential from geopotential height"""
        g = 9.80665  # m/s²
        z = deps['H'] * g
        z.attrs['long_name'] = 'Geopotential'
        z.attrs['units'] = 'm²/s²'
        return z
    
    def _calculate_pm25(self, deps: Dict[str, xr.DataArray]) -> xr.DataArray:
        """Calculate PM2.5 from aerosol species"""
        return (deps['SSSMASS25'] + deps['DUSMASS25'] + deps['BCSMASS'] +
                deps['OCSMASS'] + deps['SO4SMASS'] + deps['NISMASS25'] +
                deps['NH4SMASS'])
    
    def _load_from_yaml(self, config_path: str) -> None:
        """Load variable metadata from YAML file"""
        with open(config_path) as f:
            config = yaml.safe_load(f)
        
        self.scale_map = config['variable_scales']
        self.unit_map = config['variable_units']
        self.long_name_map = config['variable_long_names']
        self.calculable_vars = config['calculable_variables']
        self.prithvi_levels = config.get('prithvi_pressure_levels', {})
        
        # Register calculators
        self._register_calculators()
    
    def _load_defaults(self) -> None:
        """Load hard-coded defaults from constants.py"""
        from model.constants import (
            VARS_SCALE_MAP, VARS_UNIT_MAP, VARS_LONG_MAP,
            CALCULABLE_VARS, PRITHVI_PRESSURE_LVLS
        )
        
        self.scale_map = VARS_SCALE_MAP
        self.unit_map = VARS_UNIT_MAP
        self.long_name_map = VARS_LONG_MAP
        self.calculable_vars = CALCULABLE_VARS
        self.prithvi_levels = PRITHVI_PRESSURE_LVLS
        
        self._register_calculators()
    
    def _register_calculators(self) -> None:
        """Map calculable variable names to calculation methods"""
        self._calculators = {
            'D2m': self._calculate_d2m,
            'LOGAOD': self._calculate_logaod,
            'Z': self._calculate_z,
            'PM25': self._calculate_pm25,
        }
    
    def _validate(self) -> None:
        """Validate internal consistency of registry"""
        errors = []
        
        # Check calculable variables have registered calculators
        for var_name in self.calculable_vars.keys():
            if var_name not in self._calculators:
                errors.append(f'No calculator for {var_name}')
        
        # Check calculable variables have metadata
        for var_name in self.calculable_vars.keys():
            if var_name not in self.scale_map:
                errors.append(f'{var_name} missing scale factor')
            if var_name not in self.unit_map:
                errors.append(f'{var_name} missing units')
            if var_name not in self.long_name_map:
                errors.append(f'{var_name} missing long name')
        
        if errors:
            raise ValueError(f'Variable registry validation failed:\n' +
                           '\n'.join(f'  - {e}' for e in errors))

    """Base exception for all weather stats pipeline errors"""
    pass

class ConfigError(WeatherStatsError):

        super().__init__(message)

class DatasetValidationError(WeatherStatsError):
    """Dataset validation failed (missing variables or pressure levels)"""
    def __init__(self, dataset_type: str, missing_vars: List[str] = None,
                 missing_levels: List[int] = None):
        self.dataset_type = dataset_type
        self.missing_vars = missing_vars or []
        self.missing_levels = missing_levels or []
        super().__init__(self._format_message())
    
    def _format_message(self):
        parts = [f'{self.dataset_type} validation failed']
        if self.missing_vars:
            parts.append(f'Missing variables: {", ".join(self.missing_vars)}')
        if self.missing_levels:
            levels_str = ', '.join(str(lv) for lv in self.missing_levels)
            parts.append(f'Missing pressure levels: {levels_str}')
        return ' - '.join(parts)

class FileNotFoundError(WeatherStatsError):
    """Required input file not found"""
    def __init__(self, file_type: str, search_paths: List[str],
                 context: str = None):
        self.file_type = file_type
        self.search_paths = search_paths
        self.context = context
        super().__init__(self._format_message())
    
    def _format_message(self):
        msg = f'{self.file_type} file not found'
        if self.context:
            msg += f' ({self.context})'
        msg += f'\nSearched paths:\n'
        msg += '\n'.join(f'  - {p}' for p in self.search_paths)
        return msg

MIGRATION STRATEGY
================================================================================

How to transition from old to new architecture without breaking everything.

Strategy: Parallel Implementation
----------------------------------
Don't replace old code immediately. Build new alongside old, then switch.

Step 1: Create New Code Alongside Old
  - Create new files (don't modify old ones yet)
  - Implement new classes
  - Write tests for new classes
  - Verify tests pass

Step 2: Add Adapter/Facade Layer
  - Create adapter that wraps new code with old interface
  - Existing code continues using old interface
  - Adapter translates to new code
  
    # adapter.py
    class BatchDatasetProcessorAdapter:
        """Adapter that wraps new architecture with old interface"""
        def __init__(self, config):
            # Create new components
            self.grid_manager = GridManager()
            self.file_resolver = FileResolver()
            # etc.
        
        def process_batch(self, **kwargs):
            """Old interface method delegates to new architecture"""
            # Translate old kwargs to new API
            # Call new code
            # Translate results back to old format
            return old_format_result

Step 3: Switch One Module at a Time
  - Update one caller to use new code directly
  - Test thoroughly
  - If problems, easy to roll back
  - Once stable, update next caller

Step 4: Remove Adapter and Old Code
  - Once all callers updated, remove adapter
  - Remove old code
  - Clean up

Example Migration for GridManager:

    # Week 1: Create new GridManager
    # model/grid_manager.py created with tests
    
    # Week 2: Keep old code, add wrapper
    class BatchDatasetProcessor:
        def _create_target_grid(self):
            # OLD CODE STILL HERE
            # But add this:
            if USE_NEW_GRID_MANAGER:
                manager = GridManager()
                return manager.create_grid(...)
            # else: old code
    
    # Week 3: Test with flag enabled
    USE_NEW_GRID_MANAGER = True  # Test thoroughly
    
    # Week 4: Remove old code
    class BatchDatasetProcessor:
        def _create_target_grid(self):
            manager = GridManager()
            return manager.create_grid(...)

Benefits of This Approach
--------------------------
- No big bang switchover
- Easy to roll back if issues
- Can test new code in production incrementally
- Old code works while developing new
- Reduces risk significantly

Rollback Plan
-------------
If problems occur with new code:
1. Set USE_NEW_CODE flag to False
2. Old code path activates immediately
3. Debug new code without time pressure
4. Fix and try again

Version Control Strategy
-------------------------
- Create feature branch for refactoring
- Merge small PRs regularly (per component)
- Each PR independently reviewable
- Main branch stays stable


================================================================================
COMMON PITFALLS TO AVOID
================================================================================

Based on refactoring experience, watch out for:

Pitfall 1: Trying to Do Everything at Once
-------------------------------------------
Problem: Start refactoring multiple areas simultaneously
Result: Large unfinished changes, nothing working
Solution: Complete one component fully before starting next

Pitfall 2: Not Writing Tests First
-----------------------------------
Problem: Refactor without test coverage
Result: Break functionality without noticing
Solution: Write tests for existing behavior before refactoring

Pitfall 3: Changing Behavior While Refactoring
-----------------------------------------------
Problem: "While I'm here, let me also fix/improve..."
Result: Can't tell if new bugs are from refactoring or changes
Solution: Refactoring = same behavior, different structure. No new features.

Pitfall 4: Making Classes Too Generic
--------------------------------------
Problem: "What if we need this for other use cases..."
Result: Overly complex, hard to use
Solution: Solve current problem simply. Refactor later if needed.

Pitfall 5: Not Communicating Changes
-------------------------------------
Problem: Surprise other developers with big changes
Result: Merge conflicts, confusion, frustration
Solution: Communicate plan, get feedback, coordinate

Pitfall 6: Skipping Documentation
----------------------------------
Problem: "Code is self-documenting"
Result: Six months later, nobody understands architecture
Solution: Document architecture decisions as you go

Pitfall 7: Perfectionism
-------------------------
Problem: "Just one more improvement before merging..."
Result: Never finish, branches get stale
Solution: Good enough is good enough. Merge and iterate.
