WEEKS 1-2: ERROR HANDLING + VARIABLE REGISTRY
==============================================

Why These First:
- Error handling: Easier debugging (saves time immediately)
- Variable registry: You'll need to add variables/models (prevents future pain)

Week 3: Fix Parallel Executor Pattern
--------------------------------------
Goal: Prevent "missing file path" bugs

Day 1-2: Create simple DatasetResult class
    class DatasetResult:
        def __init__(self, path, was_cached, dataset_type):
            self.path = path  # Always set!
            self.was_cached = was_cached
            self.dataset_type = dataset_type

Day 3-4: Update dataset_parallel_executor.py
    Make sure EVERY code path returns DatasetResult with path set
    
    def _check_existing(dataset_type):
        existing = find_existing_file(dataset_type)
        if existing:
            return DatasetResult(path=existing, was_cached=True, 
                               dataset_type=dataset_type)
        return None
    
    def _build_dataset(dataset_type):
        path = do_build()
        return DatasetResult(path=path, was_cached=False,
                           dataset_type=dataset_type)

Day 5: Update coordinator to use DatasetResult
    result = build_dataset('fcst')
    dataset_files['fcst'] = result.path  # Always has path!

TESTING STRATEGY (MINIMAL)
===========================

Given time constraints, focus on:

1. Smoke Tests (Run After Each Change)
   - Does the pipeline still run end-to-end?
   - Do test datasets process correctly?
   - Are error messages clear?

2. Critical Path Tests (Week 5)
   - Test run_pipeline() with existing datasets
   - Test run_pipeline() with missing files
   - Test statistics calculation
   - 5-10 tests total

3. Manual Testing
   - Run on real data periodically
   - Check outputs look correct
   - Verify error handling works

SKIP: Unit tests for everything
SKIP: Integration tests for all paths
SKIP: Performance testing
SKIP: Edge case coverage


WHAT TO SKIP (SAVE FOR LATER)
==============================

Do NOT attempt in 6 weeks:
- Full god class refactoring
- Comprehensive test suite
- Dependency injection everywhere
- Interface definitions
- Abstraction layer cleanup
- Major architectural changes


RISK MITIGATION (LOW BUDGET)
=============================

Since testing is limited:

1. Work on feature branch
   - Easy to roll back
   - Can test in isolation

2. Make small commits
   - Each commit compiles and runs
   - Easy to bisect if bugs appear

3. Test on small dataset first
   - Catches issues quickly
   - Less time wasted

4. Keep old code commented
   - Can uncomment if new code breaks
   - Remove after 1 week of stability
