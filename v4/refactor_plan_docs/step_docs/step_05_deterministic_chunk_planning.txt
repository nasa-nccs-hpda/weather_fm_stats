Step 5: Make Init-Date Chunk Planning And Merge Contracts Deterministic

Status
- Implemented locally; pending Discover validation.

Original Plan
- This step replaces the earlier direct jump into statistics parallelism.
- The goal is to define deterministic chunk and merge behavior before adding more chunked processing.

Planned Work
- Create one clear chunk planning approach for:
  - existing forecast dataset chunks in pipeline Stage 2
  - future regional/global statistics chunks in pipeline Stage 3
- Define a chunk as an init-date range with explicit metadata:
  - chunk_index
  - inclusive start_idx and end_idx against the full configured init-date sequence
  - selected init_dates after exclusions are applied
  - empty/skipped status when all dates in the range are excluded
  - expected output filename or filename stem
- Build chunk ranges from the full configured init-date sequence before exclusions.
- Apply exclusions inside each chunk and record the resulting selected dates.
- Preserve empty chunks as explicit skipped chunks instead of silently losing them.
- Make chunk output names deterministic from chunk metadata, not from worker completion order.
- Make chunk result ordering deterministic by chunk_index.
- Define the merge contract that forecast and future statistics chunking must follow:
  - merge only chunks expected by the chunk plan
  - merge in chunk_index/init-date order
  - treat skipped chunks as complete only when explicitly marked skipped
  - fail the merge if a required chunk output is missing
  - perform minimum output validation before cleanup
  - do not use filename glob order as the source of truth
- Keep cleanup conservative until merged output validation is strong enough.

Out Of Scope For This Step
- Do not implement statistics parallelism yet.
- Do not redesign all dataset processing abstractions.
- Do not implement full restart/resume checkpointing.
- Do not implement deep scientific validation of merged statistics values.
- Do not add aggressive cleanup behavior; define the cleanup rules first and keep deletion conservative.

Planned Files To Inspect Or Touch
- model/dataset_parallel_executor.py
- model/dataset_processor.py
- controller/cli_controller.py
- model/config_model.py, only if a new chunk setting is genuinely needed
- refactor_plan_docs/v4_refactor_plan.txt

Planned Acceptance Criteria
- Forecast dataset chunk planning has stable chunk indices and expected output names.
- Empty chunks caused by excluded dates are represented as skipped chunks.
- Chunk results are reported in deterministic chunk_index order.
- Forecast merging can be described from the chunk plan: expected files, skipped chunks, and merge order are explicit.
- Missing required chunk outputs fail before merge or cleanup.
- The planned chunk metadata is sufficient for future statistics chunking.
- Existing manual chunk and merge commands remain available for debugging.

Actual Implementation
- Added a shared chunk planning helper in model/chunk_plan.py.
- Added ChunkSpec records with:
  - chunk_index
  - start_idx
  - end_idx
  - all_dates
  - selected_dates
  - status
  - output_path
- Added InitDateChunkPlanner to build chunks from the full configured init-date sequence before exclusions.
- Applied exclusions inside each chunk.
- Marked chunks with no selected dates as skipped.
- Added JSON writing for chunk plans so planned and final chunk statuses can be inspected later.
- Updated forecast dataset chunk execution to use ChunkSpec records instead of raw start/end tuples.
- Forecast workers now return chunk_index, chunk_id, start/end indices, output_path, status, and processed date count.
- Forecast chunk results are sorted by chunk_index before being returned.
- Forecast merge can now accept the chunk plan and merge only expected required chunk files.
- Forecast merge now treats skipped chunks as complete only when they are explicit in the plan.
- Forecast merge now fails if an expected required chunk file is missing.
- Forecast merge keeps the old glob-based behavior when no chunk plan is supplied, preserving manual --merge_forecast_chunks debugging.
- Forecast merge validates the merged forecast file before deleting expected chunk files.
- Fixed Stage 2 dataset path resolution for fcst, ana, and clim.
- Added shared final dataset path resolution so existing validated datasets keep their original paths, while newly saved datasets resolve to outputs/<generated_filename>.
- Removed forecast-only final path patching in favor of one rule for all three source datasets.

Validation Notes
- Not run locally.
- Validation should be performed on Discover by running a small forecast-processing pipeline case.
- Recommended checks:
  - chunk_plan_fcst.json is written under outputs/<info_dir>/tmp.
  - chunk records are ordered by chunk_index.
  - excluded-date-only chunks are marked skipped.
  - required chunks produce the expected output paths.
  - forecast merge fails if a required chunk file is missing.
  - forecast merge deletes only expected required chunk files after successful validation.
  - manual --merge_forecast_chunks still works without a chunk plan.
  - Stage 2 reports fcst, ana, and clim dataset paths with usable paths for statistics.
  - Newly created ana/clim paths include the outputs/ prefix.
  - Existing datasets found through dir_loc keep their original discovered paths.

Known Limits After This Step
- Statistics chunking is not implemented yet.
- Statistics merge still uses the older glob-based behavior.
- Full restart/resume checkpointing is not implemented.
- The chunk plan JSON is written for debugging and future resume support, but the pipeline does not yet reload it.
- Merged forecast validation is intentionally basic: the final file must open, include init_date, and match the expected init_date count.
