Step 6: Parallelize Statistics Calculation In Python

Status
- Small Discover validation succeeded; larger-YAML validation in progress.

Original Plan
- Use the deterministic chunk plan to split regional and global statistics by init_dates.
- Run statistics chunks with ProcessPoolExecutor inside the single pipeline job.
- Write chunk outputs with expected deterministic names.
- Merge statistics chunks automatically only after all required chunks finish successfully or are explicitly skipped.

Planned Work
- Reuse the Step 5 init-date chunk planner for statistics chunks.
- Add statistics-specific runtime settings only if needed, such as:
  - pipeline_chunk_size_stats
  - pipeline_max_workers_stats
- For each requested statistics branch:
  - build the stats chunk plan from the same init_dates used by Stage 2
  - skip chunks with no selected init_dates
  - run required chunks in local worker processes
  - write deterministic chunk output files
  - sort chunk results by chunk_index
  - merge only expected required chunks after all required chunks complete
- Preserve the existing manual stats chunk behavior for debugging where practical.
- Keep regional and global branch behavior consistent with the Step 1 failure policy.

Out Of Scope For This Step
- Do not make regional and global branches run concurrently unless it falls out naturally and safely.
- Do not implement full restart/resume checkpointing.
- Do not redesign all statistics calculations.
- Do not remove legacy manual stats chunk commands yet.
- Do not implement deep old-vs-new scientific validation; that remains a later step.

Planned Files To Inspect Or Touch
- model/chunk_plan.py
- model/statistics_processor.py
- controller/cli_controller.py
- model/config_model.py
- possibly a new model/statistics_parallel_executor.py if keeping orchestration separate is cleaner
- refactor_plan_docs/step_docs/step_06_parallel_statistics_calculation.txt

Planned Acceptance Criteria
- Pipeline statistics can run by init-date chunks for regional stats.
- Pipeline statistics can run by init-date chunks for global stats.
- Stats chunk output filenames are deterministic and tied to chunk_index or chunk metadata.
- Stats chunk results are reported in deterministic chunk_index order.
- Stats merge consumes expected chunk files from the chunk plan, not arbitrary glob order.
- A missing required stats chunk fails the branch before cleanup.
- Skipped chunks are explicit and do not block merge.
- Final regional/global statistics outputs match the existing non-chunked output naming convention.

Actual Implementation
- Added model/statistics_parallel_executor.py.
- Added run_parallel_statistics_branch(...) to orchestrate one regional or global stats branch with init-date chunks.
- Reused InitDateChunkPlanner from Step 5 for statistics chunk plans.
- Added chunk plan files:
  - chunk_plan_stats_reg.json
  - chunk_plan_stats_glo.json
- Added ProcessPoolExecutor execution for required statistics chunks.
- Kept regional and global branches sequential at the pipeline level to avoid nested oversubscription.
- Each stats worker creates its own StatisticsProcessor and runs the existing chunk mode:
  - run_regional_statistics(..., using_chunks=True, skip_avg=True)
  - run_global_statistics(..., using_chunks=True, skip_avg=True)
- Stats chunk filenames now use deterministic chunk IDs from the plan.
- Stats chunk results are sorted by chunk_index before branch completion.
- Updated StatisticsProcessor.merge_statistics_files(...) to accept an optional chunk plan.
- Plan-aware stats merge now:
  - merges only expected required chunk files
  - fails if a required chunk file is missing
  - validates expected init_date count before saving final merged output
  - preserves the old glob fallback when no plan is supplied
- Added runtime settings:
  - pipeline_chunk_size_stats
  - pipeline_max_workers_stats
- Added conservative default stats worker behavior: use configured workers when provided, otherwise cap automatic stats workers at 4.
- Added per-branch memory fields to the pipeline summary and final run log when resource usage is available:
  - regional_max_memory_mb
  - global_max_memory_mb
  - pipeline_max_memory_mb

Testing Observation
- The small Discover run showed the statistics chunking and plan-aware stats merge working as expected.
- Larger-YAML testing revealed that source dataset regridding can still be slow before statistics begin.
- The likely bottleneck is ana/clim dataset regridding, because Step 4 parallelized forecast chunks but left ana and clim processing in the sequential follow-up path.
- This observation motivated the new Step 7: parallelize analysis and climatology dataset creation in Python.

Known Limits After This Step
- Full restart/resume checkpointing is not implemented.
- The pipeline writes stats chunk plans but does not yet reload them.
- Regional and global branches still run sequentially; each branch can run chunks in parallel.
- Memory reporting uses process max RSS when available on the platform.
