Step 7: Strengthen Regional And Global Branch Independence

Status
- Planned.

Purpose
- Make the regional and global statistics branches behave as independent pipeline branches after shared source datasets are built.
- Keep shared dataset creation as one Stage 2 step, then let each requested statistics branch report its own result clearly.
- Preserve the Step 1 behavior contract: when failure policy permits, one branch failure should not hide or prevent the other branch result.

Current State
- Regional and global statistics already run as separate branch calls in pipeline mode.
- Each branch now uses deterministic statistics chunk planning from Step 6.
- Branch results are written to the pipeline summary with status, error, chunk counts, worker counts, and memory usage.
- Branch execution is still sequential, which is acceptable for v4 unless a later resource-control decision changes it.

Planned Work
- Review the current branch result contract returned by run_stats_branch(...) and run_parallel_statistics_branch(...).
- Make regional/global branch result fields consistent for success and failure cases.
- Ensure partial_ok always attempts all requested branches, even if one branch fails.
- Ensure fail_fast stops after the first failed branch and records the skipped/not-run state clearly if needed.
- Add explicit branch output fields if they can be resolved reliably without opening large datasets.
- Make final pipeline status derive only from requested branch statuses and the configured failure policy.
- Keep regional and global branches sequential for now to avoid nested worker oversubscription.
- Keep all changes scoped to pipeline orchestration and summary behavior unless a correctness issue is found.

Out Of Scope For This Step
- Do not parallelize regional and global branches at the same time.
- Do not change the statistics calculations.
- Do not add full restart/resume checkpointing.
- Do not redesign source dataset creation.
- Do not add ana/clim dataset parallelization.

Planned Files To Inspect Or Touch
- controller/cli_controller.py
- model/statistics_parallel_executor.py
- model/config_model.py, only if a new runtime setting is truly needed
- refactor_plan_docs/v4_refactor_plan.txt
- refactor_plan_docs/step_docs/step_07_branch_independence.txt

Planned Acceptance Criteria
- If stats_types=regional, only the regional branch runs and summary fields are regional-only.
- If stats_types=global, only the global branch runs and summary fields are global-only.
- If stats_types=both and pipeline_fail_policy=partial_ok, both branches are attempted even if one fails.
- If stats_types=both and pipeline_fail_policy=fail_fast, the pipeline stops after the first failed branch and reports that clearly.
- Branch status, error, chunk counts, worker counts, and memory fields are consistently present when applicable.
- Final pipeline status is easy to infer from the final log and run_summary.txt.
- Existing successful Step 6 behavior remains unchanged for normal regional+global runs.
